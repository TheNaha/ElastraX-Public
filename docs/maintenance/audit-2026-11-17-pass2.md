## Critical Bugs

### CB-01 — A recurring scheduled `/task` run replies once and then is silently swallowed (HIGH)

`src/runtime/AppRuntime.ts:147-158` derives the synthetic message id from
`platform + roomKey + instruction` only (`receivedAt` is accepted and unused), and
`src/agent/index.ts:808-826` treats a `messages` insert conflict as "duplicate provider event" and
returns before any model call. The `messages` unique index covers
`(platform, chat_room_id, provider_message_id)` for every non-placeholder id, so the *second* fire of
the same `/task …` reminder inserts the same tuple, `changes === 0`, and the room never gets a reply
again. Messages are retained 180 days, so a daily task is one reply and then months of silence.

**Verified:** read the id derivation, the insert guard, the unique index (`.where(... not in ('',
'unknown','null'))`), the scheduler call, and `ScheduledTaskMessageId` callers. No test covers a
second fire.
**Fix:** make the synthetic id unique per fire (include the fire timestamp), keeping it non-placeholder.

### CB-02 — With streaming enabled, a scheduled run's final answer is never delivered (HIGH)

`src/agent/index.ts:1229-1232` enables streaming whenever `sendMessage` and `editMessage` exist.
The scheduled-task context supplies both as stubs (`AppRuntime.ts:808,818`: `sendMessage: sendText`
and `editMessage: async () => {}`). So the first preview becomes a message and every later "edit" is
a no-op; `sentKey` keeps a value, `streamedResponseSent` stays true, the final `editMessage`
resolves, and `replyAlreadyDelivered` (line 1464) records the full answer as delivered — while the
room only ever saw truncated previews ending in `▌`.

**Verified:** read both halves. Real providers return truthy edit keys.
**Fix:** do not advertise streaming capability on the synthetic context (drop the stub
`sendMessage`/`editMessage`); the scheduled run then uses the plain `reply` path.

### CB-03 — A documented loopback LLM endpoint is rejected by `AIClient` (HIGH, integration gap)

`docs/configuration.md:22` states "http allowed only on loopback hosts", `src/config/env.ts:104,107`
validates exactly that and allows a loopback base URL without an API key, and
`test/config.test.ts:43` configures `http://127.0.0.1:8000/v1`. But
`src/ai/client.ts:175,223` runs `isValidUrl`, which returns `false` for `localhost`, `127/8`, `::1`
and every RFC1918 host, so `prepareRequest` throws on **every** request for a local model server.

**Verified:** the two validators side by side; `new URL` accepts all the rejected hosts; no test
asserts the rejection.
**Fix:** make the base-URL check accept what `validateEnv` accepts (scheme http/https, no
credentials), keeping only the cloud-metadata link-local address blocked.

### CB-04 — Admin "Retry outbox" can resurrect a delivered row and send it twice (MED-HIGH)

`src/admin/data.ts:513-523` reads the row, checks `state ∈ {failed, dead_letter}`, then updates
`state='pending'` with `WHERE id = ?` and no state predicate. Two overlapping POSTs (the button is
never disabled) or a worker claim between read and write re-arm a row the worker just marked `sent`;
the claim query (`OutboxService.ts:216`) never re-checks the idempotency key, so the same message is
delivered again.

**Verified:** read the action, the handler map (`routes.ts`), and the claim query.
**Fix:** put the state guard in the `UPDATE` (`AND state IN ('failed','dead_letter')`) and report the
miss when `changes === 0`.

### CB-05 — One transient lease-renewal error permanently closes the database, silently (MED-HIGH)

`src/db/index.ts:94-109`: the heartbeat wraps `renewDatabaseLease` in `try { … } catch { closeDatabase(handle); }`.
`closeDatabase` on the default handle sets `defaultClosed = true`, after which `getDefaultHandle()`
throws forever. A single `SQLITE_BUSY` past `busy_timeout`, or one event-loop stall longer than the
300 s TTL, therefore takes the whole process offline with no log line; the outbox timer then logs
`Outbox worker failed` once a second while every inbound message is dropped.

**Verified:** read the heartbeat, `closeDatabase`, `getDefaultHandle`, `renewDatabaseLease` (its only
failure modes are the expired-lease predicate and a thrown SQLite error).
**Fix:** treat a thrown error as transient (log, count, close only after repeated failures); log a
lost lease at error level before closing.

### CB-06 — WhatsApp media downloads have no timeout (MED)

`src/providers/whatsapp.ts:626-641` passes a controller that only `stop()` aborts. `saveMediaStream`
takes one of four global download slots and reserves up to 200 MiB *before* consuming the stream, so
a stalled media host pins a slot and its byte reservation for the process lifetime. Discord
(`discord.ts:360`) and Telegram (`telegram.ts:473`) both bound theirs.

**Verified:** read all three providers' download paths.
**Fix:** compose a download timeout with the controller signal, as Discord does.

### CB-07 — Telegram reaction feedback is dead code (MED)

`src/providers/telegram.ts:443` reads `ctx.messageReaction.type`/`.emoji.text`, but grammY's
`MessageReactionUpdated` carries `old_reaction`/`new_reaction` arrays
(`node_modules/@grammyjs/types/message.d.ts:1499-1513`), so the condition is never true and no
Telegram reaction is ever recorded; removals could never be recorded either.

**Verified:** read the handler and the installed grammY type.
**Fix:** diff `old_reaction` against `new_reaction`, recording added emoji as `removed:false` and
removed ones as `removed:true`.

### CB-08 — A post-spawn `'error'` event turns a clean exit into a spawn failure (MED)

`src/providers/process.ts:243-266`: `child.on('error')` records `spawnError` even when `child.pid`
exists, and the `close` handler prefers `spawnError` over `code === 0`. An `'error'` emitted by a
process that really ran (e.g. a failed `kill`) rejects a successful run and discards its stdout.

**Verified:** read both handlers and the settle paths.
**Fix:** only treat `'error'` as fatal when the child never started; log it otherwise.

### CB-09 — A summary-store *read* failure aborts the whole turn (MED)

`src/utils/ConversationSummarizer.ts:124` awaits `store.load(...)` outside the try that guards
`store.save`; `src/ai/summaryStore.ts:31-36` lets a database error propagate; the agent call at
`src/agent/index.ts:1089` has no catch, so a transient `app_kv` error turns every message in a
summarizing room into "An internal error occurred".

**Verified:** read the three layers.
**Fix:** degrade a failed load to "no previous summary" inside the summarizer.

### CB-10 — `link`/`info` availability check searches the catalogue by id text (MED)

`src/tools/MediaLibraryTool.ts:151-166` calls `searchItems(item_id)` — a full-text `searchTerm`
query (`JellyfinClient.ts:105-114`) — and requires the result set to contain the exact id. A GUID
never matches a title search, so both actions return `item_not_available` for any real id. The
existing test hides this because its mock omits `searchItems`.

**Verified:** read the tool, the client, and the test.
**Fix:** check existence/visibility with `getItem(item_id)` (already used by `info`).

### CB-11 — The >50 MB Telegram document fallback can never succeed (MED)

`src/providers/telegram.ts:699-724` comments that documents "have a much higher limit", but the
public Bot API caps every upload at 50 MB. A 50–200 MB buffer is downloaded, buffered, uploaded and
rejected with a raw `Request Entity Too Large` instead of a clear error.

**Verified:** read the provider; `MAX_MEDIA_BYTES` is 200 MB.
**Fix:** reject >50 MB with a clear `ProviderOperationError` before uploading, and correct the comment.

### CB-12 — `/mute` takes a required target user and then mutes the whole group (MED)

`src/tools/GroupAdminTool.ts:116-126` ignores `user` for `mute`/`unmute` and sets the group-wide
announcement flag, while the grammar (`:47-48`) and `ParameterValidator.ACTION_ARGUMENTS.groupadmin`
make `user` required. `/mute @bob` parses, succeeds, and locks the whole group while reporting the
group was muted.

**Verified:** read the tool, the grammar, the resolver order in `execute`, and
`MessageContext.setGroupSettings`.
**Fix:** drop the required `user` from the two variants (the action is group-wide by design; WhatsApp
has no per-member mute) and keep the copy in `ACTION_ARGUMENTS` aligned.

### CB-13 — `PDFTool` resolves media outside its error boundary (MED)

`src/tools/PDFTool.ts:150` calls `resolveTargetMedia(ctx)` after the `try` block ends at `:148`.
`resolveTargetMedia` awaits `ctx.mediaReady`, and provider media promises reject on a failed
download (`createLazyPromise` → `downloadDescriptor`), so a download failure throws out of the tool
instead of returning the localized error. `MediaConvertTool` already wraps this call for exactly
this reason.

**Verified:** read the tool and the provider promise chain.
**Fix:** move the call inside the guarded block.

### CB-14 — Knowledge indexing buffers the whole file before checking the size cap (MED)

`src/tools/KnowledgeTool.ts:136-140` loads all bytes and only then compares against
`MAX_INDEX_BYTES`, while provider media may be up to 200 MB. `PDFTool` was changed to `stat()` first
for this reason.

**Verified:** read both tools.
**Fix:** `stat()` first and refuse oversized files before reading.

### CB-15 — `BaseHttpClient` stops bounding a request once the headers arrive (MED)

`src/utils/BaseHttpClient.ts:118-121` clears the timeout and removes the caller-abort listener in
the `finally` around `fetch`, then reads the body at `:147` (or `:124,140`) with a controller nobody
can abort any more. An upstream that sends headers and stalls the body hangs the request forever and
cannot be cancelled.

**Verified:** read the request/response flow and all three body readers.
**Fix:** keep the timer and the listener alive until the body is consumed.

### CB-16 — A blank `WEBHOOK_*_SECRET_COMPAT_UNTIL=` crashes startup (MED)

`src/webhooks/config.ts:157-161` treats a present-but-empty value as an unparseable timestamp and
throws, even when the compat path is disabled. Every other reader in that file treats `''` as unset.

**Verified:** read the parser and the sibling readers.
**Fix:** treat an empty value as unset.

### CB-17 — The per-event subscription filter is ignored on the instant webhook path (MED)

`src/webhooks/WebhookServer.ts:304,381` call `getNotificationRooms`/`getAdminNotificationRooms`
without the event type; `matchesEvent` returns `true` when no event type is given
(`NotificationSubscriptionService.ts:97-101`). A subscription narrowed with `notifyTypes` therefore
receives every Seerr/Jellyfin event, while the digest path honours the same column. The event name is
available (`notification_type` / `NotificationType`).

**Verified:** read the intake path, the service, and the digest's `wantsDigest` filter.
**Fix:** pass the event type through.

### CB-18 — The media-quota cache is written before the incoming file and never updated (MED)

`src/utils/mediaShared.ts:210` stores totals that exclude the file being saved; nothing increments
the cache after `rename` (only `deleteSavedMedia` invalidates it). Within the 60 s TTL every save
checks `cache + thisFile` only, so a burst can overshoot the byte/file quota by the whole burst.

**Verified:** read `reconcileMediaQuota`, both save paths, and every cache writer.
**Fix:** account for the saved file in the cache after a successful rename.

### CB-19 — A turn that uses its whole tool budget answers "internal error" (MED)

`src/agent/index.ts:1220,1443-1450`: the loop runs at most `maxToolIterations` times and every
iteration may request tools, so a turn that legitimately uses the full budget ends with
`isDone === false` and the accumulated assistant text is discarded.

**Verified:** read the loop, the budget config, and the post-loop branch.
**Fix:** make the final iteration text-only (no tool definitions) so the model must answer.

### CB-20 — A streamed bubble adopted by a disabled progress tracker is never finalised (LOW-MED)

`src/agent/toolProgress.ts:161-165` adopts the key even when `disabled` is set, and
`syncMessage` then refuses to edit, so `src/agent/index.ts:1304-1311` skips the finalising edit and
the bubble keeps its `▌` cursor forever.

**Verified:** read both conditions.
**Fix:** don't adopt when the tracker cannot edit.

### CB-21 — The search tools render an empty reply when every hit is untrusted (LOW)

`src/tools/GameSearchTool.ts:46-48` / `SoftwareSearchTool.ts:46-48` filter results after the base
class has decided there were results, so an all-untrusted set yields the header with no items and no
"no results" message.

**Verified:** read the base pipeline and both overrides.
**Fix:** fall back to the no-results message when the filtered set is empty.

### CB-22 — A clock emoji is classified as positive feedback (LOW)

`src/utils/feedback.ts:28` includes `\u{1F550}` (🕐) in the positive set — a copy error, not a
verdict glyph. Every clock reaction pollutes the quality metric and the eval log.

**Verified:** read the set and `classifyReaction`.
**Fix:** remove the entry.

### CB-23 — A truncated tool result reaches the model with no marker (LOW)

`src/agent/index.ts:398` keeps only `.value` from `turnBudget.constrainTextResult`, discarding
`.truncated`, so the model reads a cut-off JSON/text result as if it were complete.

**Verified:** read the budget helper and the call.
**Fix:** append a truncation marker when the result was cut.

### CB-24 — `response_too_large` is reported as `invalid_response` (LOW)

`src/ai/client.ts:320-332` throws the size error inside the same `try` that converts everything to
`invalid_response`, destroying the diagnostic code.

**Verified:** read the block.
**Fix:** run the size guard outside the JSON-conversion catch.

### CB-25 — `pinout` rotated-log support is unreachable (LOW)

`src/tools/OwnerTool.ts:230-231` filters names ending in `.log` and then tests for `.log.N`, which
can never match, so rotated shards are invisible.

**Verified:** read the filter and the flag together.
**Fix:** include rotated names in the filter.

### CB-26 — The SSRF proxy ignores client aborts and has no CONNECT timeout (MED)

`src/providers/ssrf.ts:170-180` never destroys the upstream request when the proxied client goes
away, and attaches no error listener to `response`; `handleConnect` (`:196-215`) has no connect
timeout, so a blackholed SYN pins both sockets until the caller's own timeout and the client gets a
bare reset instead of `502`.

**Verified:** read both handlers and the socket tracking.
**Fix:** tear down upstream on response close/error and time out CONNECT.

### CB-27 — `levenshtein` stores distances in a `Uint16Array` (LOW)

`src/utils/similarity.ts:32,64` overflows for an edit distance above 65535 (two ~70 k-char strings),
silently returning a wrong distance. Current callers pass command names, so this is latent.

**Verified:** read the implementation and all call sites.
**Fix:** widen to `Uint32Array`.

### CB-28 — An unparseable backup manifest makes its snapshot look like an orphan (MED)

`src/db/backup.ts:257-267` builds the `live` set only from manifests `parseManifest` accepts, so a
manifest it cannot read (bit rot, a future `formatVersion`, a hand edit) causes the matching `*.db`
to be deleted on the next run after the grace window, with no log.

**Verified:** read `parseManifest`, the sweep, and `backupDatabase`.
**Fix:** skip the sweep (and warn) when any manifest fails to parse.

### CB-29 — The inbox lease (120 s) is shorter than a turn can be and is never renewed (MED)

`src/messaging/InboxService.ts:9` sets `LEASE_MS = 120_000`; nothing renews it between `claim` and
`complete`, and a turn is bounded only by tool iterations with 15 s provider timeouts. The hourly
`recoverStranded` then returns a *live* worker's row to `received`, its `complete()` is rejected, and
a duplicate provider delivery re-runs the whole turn (duplicate reply and tool side effects).

**Verified:** read every writer of `lease_expires_at`, the recovery sweep, and the runtime handler.
**Fix:** raise the lease to 10 minutes (recovery still happens on the hourly sweep).

### CB-30 — Telegram `sendToChat` drops reply options (LOW)

`src/providers/telegram.ts:657` forwards only `(chatId, text)`, so a cross-chat send cannot be
cancelled by the outbox signal and mentions are ignored, unlike WhatsApp/Discord.

**Verified:** read the three implementations against `MessageContext.sendToChat`.
**Fix:** forward `options`.

### CB-31 — Discord mirrors only quoted attachment #0 (LOW)

`src/providers/discord.ts:341` updates `ctx.quoted.mediaPath` only for `descriptor.index === 0`,
while WhatsApp mirrors whichever quoted attachment was selected; a reply to a multi-attachment
message that selects #2 leaves `ctx.quoted.mediaPath` pointing at #1.

**Verified:** read both providers.
**Fix:** mirror any selected quoted attachment.

### CB-32 — The admin "Documents" column counts chunks, not documents (MED)

`src/admin/data.ts:164-173` counts `memories` rows with `category='document'`, but room knowledge
stores one row per *chunk* (`roomKnowledge.ts:191-199`) and the canonical reader
`listRoomDocuments` collapses them by `documentIdOf`. A 40-chunk PDF shows 40 documents.

**Verified:** read the writer, the reader, and the admin query.
**Fix:** dedupe by `documentIdOf` over the ids for the page's rooms.

### CB-33 — "Inbox stranded" counts only one of three stranded states (LOW)

`src/admin/routes.ts:584` reads `byState.received` while the table below lists
`received + processing + failed`.

**Verified:** read the stat and `inboxInventory`.
**Fix:** sum the three.

### CB-34 — A wrong login token silently reloads the form (LOW)

`src/admin/routes.ts:461` turns every `401` into `location.href = '/admin/login'`; the login view
answers a wrong token with `401 {error:'Invalid token.'}`, so the page reloads and the error is never
shown, while `429` does show one.

**Verified:** read `api()`, the login view, and the server's login branch.
**Fix:** let the login call surface its own error.

## Integration Gaps (flagged, not changed)

- **IG-01** `OutboxService.enqueueText` (`:104-128`) returns the existing id for a `dead_letter` or
  `sent` row without storing the new text, and `AppRuntime.enqueueWebhook` still answers
  `accepted: true`, so a redelivery after the in-memory replay cache expired is acknowledged and
  never delivered. Re-arming a dead-letter row is a policy decision (infinite retries vs loss).
- **IG-02** Webhook authentication and the body read happen before the rate limiter
  (`WebhookServer.ts:519-577`), so unauthenticated traffic can spend `maxBodyBytes` and HMAC work
  unthrottled. Reordering changes which requests get 429.
- **IG-03** A webhook send timeout returns `502` and releases the replay reservation
  (`WebhookServer.ts:106-113,282-285`) although a provider that ignores the abort can still deliver,
  so the sender's retry can double-send. Needs provider-level idempotency.
- **IG-04** An inbox duplicate that arrives during a retry backoff is accepted by `admit()` and then
  dropped by `claim()` with no log (`InboxService.ts:78-84,121-122` + `AppRuntime.ts:323`), and no
  scan ever re-dispatches `failed` rows.
- **IG-05** The migration lease is never renewed (`src/db/index.ts:228-245`), so a migration longer
  than 300 s can be run concurrently by a second process.
- **IG-06** A stored room reference containing `:` (e.g. a configured `!abc:matrix.org` destination)
  is parsed as a foreign-platform key and every delivery is refused (`roomKeys.ts:133-140`).
- **IG-07** A `207` delivery failure body returns server-side subscription room ids and a subscriber
  count to the external media service (`WebhookServer.ts:270-288`).

### Review follow-ups (2026-11-17, second round)

An independent reviewer read the full diff and found one blocking bug plus
several refinements. All were applied:

1. **Blocking**: the Inbox view called `strandedInboxCount`, which does not
   exist (`APP_JS` is a string, so `tsc`/eslint never parsed it). Fixed, and a
   new test executes every embedded view against a minimal DOM stub so an
   undeclared identifier fails the gate.
2. The inbox claim lease was raised to 10 minutes but the worst configured turn
   is longer; it is now derived from `AI_MAX_TOOL_ITERATIONS`, the AI timeouts and
   the tool timeout, bounded to 10–60 minutes.
3. The SSRF CONNECT timeout now flushes the 504 before the client socket is
   dropped (the upstream close handler was destroying it first).
4. The forced final round flattens the tool protocol
   (`ModelRouter.stripToolProtocol`) instead of sending tool results with no tool
   definitions, which some OpenAI-compatible servers reject, and falls back to
   the last usable assistant text if the model still emits a tool call.
5. The lease-heartbeat failure threshold is derived from the TTL instead of a
   fixed 3, so a stall just short of the TTL no longer closes the handle.
6. A timed-out error-body read is reported as `TIMEOUT`, not `HTTP_ERROR`.
7. `KnowledgeTool` stats through the `mediaStorageDeps` seam.
8. `AIClient`'s residual metadata check is documented as a courtesy, not a guard.

Known limitation accepted: `roomInventory` now reads chunk ids for the page's
rooms and collapses them in JS (instead of one grouped count per room). That is
proportional to the knowledge base of the visible rooms and is the only correct
way to count documents, because chunk ids embed their document id after the last
underscore.

Remaining untested paths (exercised only by the full suite, not focused tests):
the `BaseHttpClient` body-timeout abort, the SSRF CONNECT timeout, the Telegram
reaction diffing and 50 MB guard.
