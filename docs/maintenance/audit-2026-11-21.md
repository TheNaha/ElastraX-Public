## Critical / high

### C-01 A crashed turn is a silent drop: the dedupe insert precedes all work
`src/agent/index.ts:860-878` — `handleIncomingMessage` inserts the inbound
`messages` row (unique on `providerMessageId`) **before** any work, and on a
conflict logs "Duplicate provider event ignored" and returns with **no reply**.
The outer `catch` deliberately rethrows so "the caller owns durable delivery
state"; `InboxService.admit` re-admits a `failed`/`received` row as accepted
(`reason: 'duplicate'`, `src/messaging/InboxService.ts:106-112`) and the turn
re-runs. But that retry hits the now-conflicting insert and returns silently, so
a provider redelivery after a crash mid-turn is acknowledged and never answered.

**Not fixed here.** An agent-side "was this answered?" check cannot distinguish a
genuine duplicate (already answered) from a crashed turn (inbound recorded, no
answer): the assistant row stores no `providerMessageId`, and the outbox row is
written *after* the response is generated, so neither survives a mid-turn crash.
The correct fix is a durable delivery/replay layer — the deferred D-02 (pass 5).
Recorded here as a confirmed silent-drop path; see D-03.

### C-02 An unterminated ` thinking` block ships as the final answer
`src/agent/index.ts:1476` (also `:1342`, `:1425`, `:1451`) uses `stripThinkTags`,
which only removes a **closed** `<think>…</think>` pair
(`src/utils/textUtils.ts:16-18`, pinned by `test/textUtils.test.ts:13`). A stream
that ends inside a reasoning block after emitting visible text (truncated
`finish_reason`, or a provider that opened the tag and stopped) yields e.g.
`"Hi  thinking…"` as the final, persisted answer — the user and every later
turn's history see the model's chain of thought. The streaming *preview* already
uses `stripPartialThinkTags` (`:1388`), and `ModelRouter` uses it for its
restart decision (`:541`, `:563`); only the agent's final-isation paths were
missed.
**Fix:** use `stripPartialThinkTags` at the four finalisation sites (final
stream text, bubble finalisation, intermediate bubble, `lastAssistantText`).
`stripThinkTags` stays for the non-streaming `extractAssistantText` (a complete
object, not a partial stream).

## Bugs (fixed)

- **B-01** `deliveredUserVisible = true` is set *after* the assistant-row insert
  (`src/agent/index.ts:1602` then `:1621`), contradicting the comment at
  `:1617-1620` that says it is set before the bookkeeping write. If that insert
  throws (busy/closed DB during shutdown) while `streamedResponseSent === true`,
  the `catch` at `:1656` sees `false` and sends a second
  "internal error" reply on top of the answer the user already read — the exact
  contradiction the flag exists to prevent. Set the flag before the insert.
- **B-02** Loop exhaustion persists intermediate narration as the final answer
  (`src/agent/index.ts:1593`): `lastAssistantText` is set from *every* step
  (`:1451`, `:1516`), including tool-calling rounds ("Let me search…"). On
  `iteration > maxToolIterations` the persisted assistant turn is that
  narration, read back on later turns as a completed answer. Only adopt the
  final round's text here; fall back to `internalErrorText` otherwise.
- **B-03** Telegram `downloadMedia` calls `bot.api.getFile()` before the 60 s
  timer and before the controller is registered (`src/providers/telegram.ts:544`),
  so a stalled `api.telegram.org` holds the turn for grammy's default
  `timeoutSeconds: 500` (~8 min), unaffected by `stop()`. WhatsApp and Discord
  bound the whole download. Move `getFile` inside the timed/abortable region.
- **B-04** Discord `forwardMessage` fetches attachments with
  `AbortSignal.timeout(30_000)` and no caller signal
  (`src/providers/discord.ts:594-612`); the controller is not in
  `mediaControllers`, so `stop()` and an aborted turn keep fetching/buffering.
  Thread the caller signal through and register the controller.
- **B-05** WhatsApp `group-participants.update` handler lacks the
  `isCurrent(socket, generation)` guard every sibling handler has
  (`src/providers/whatsapp.ts:454-456`): a superseded socket's event mutates the
  process-global admin cache for a room the bot may no longer be in.
- **B-06** The pre-auth webhook throttle is a no-op behind the documented
  reverse proxy (`src/webhooks/WebhookServer.ts:626`): it is skipped when the
  peer is loopback, but behind a proxy every peer is `127.0.0.1`, and the
  `ip:`-keyed delivery limiter is *also* dropped for loopback
  (`src/webhooks/utils.ts:311`), so a failed secret is limited by nothing. Give
  the pre-auth limiter its own key that survives the proxy case (key on the
  forwarded peer when present, else the socket IP), so unauthenticated attempts
  are actually bounded.
- **B-07** `readRequestBytesWithLimit` races `readBody()` against a timeout
  (`src/webhooks/utils.ts:184`) but never attaches a handler to the losing
  branch: if `readBody()` rejects after the timeout (e.g. the 413 cancel), the
  rejection is unhandled and `reader.releaseLock()` can run against a pending
  read. Attach a no-op catch to the losing promise.

## Integration / consistency (fixed)

- **I-01** `TurnBudget.runToolCalls` (`src/ai/turnBudget.ts:161-183`) calls
  `beginParallelCall()` and `recordToolResult()` *outside* the `try`, so a
  `TurnBudgetExceededError` escapes to `Promise.all` while sibling workers keep
  running and `results` is half-filled — after `claimToolCalls` already charged
  the budget. `grep` shows no production caller (D-17, pass 5), so this is a
  latent landmine: move the budget calls inside the `try` so a rejection is
  captured like any other task error.
- **I-02** `ctx.signal` is not honoured inside the inference loop
  (`src/agent/index.ts:1298-1585`): `MessageQueue.beginStop` aborts the running
  controller, but `AIClient` builds its own `timeoutSignal` and the tool loop
  never checks `ctx.signal.aborted`, so after shutdown the turn keeps issuing
  LLM and tool calls (up to `maxToolIterations`) while the DB is closing. Add
  an `aborted` check at the top of each iteration and thread `ctx.signal` into
  the streaming/envelope calls where the client accepts one.

## Tech debt (fixed)

- **T-01** `stripThinkTags`'s docstring now states explicitly that it keeps an
  unterminated block, and the finalisation sites carry a comment pointing at
  `stripPartialThinkTags` (the split existed; the call sites were inconsistent).

## Optional improvements (not implemented)

- **O-01** `ctx.signal` is not linked into `AIClient` calls (I-02); the clean fix
  is an `AbortSignal.any([ctx.signal, timeoutSignal])` in the client, which
  changes what an abort means for the fallback policy (carried from pass 6/7
  A-05). Left for a decision.
- **O-02** Intermediate narration persisted as the bot's answer (B-02) is fixed;
  the deeper question — whether a turn that exhausted its tool budget should
  tell the user it gave up — is a product decision.
