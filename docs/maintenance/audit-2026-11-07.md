## Integration Gaps

### IG-02: Three delivery paths, not one pipeline — CONFIRMED, no change (flagged)
**Location:** `src/agent/index.ts:158` (`deliverDurableText` / `OutboxService.enqueueDirectText` + `ctx.reply`), `src/runtime/AppRuntime.ts:627` (`enqueueWebhook` → `OutboxService.enqueueText`), `src/runtime/AppRuntime.ts:785/876` (`processOutbox` poller → `provider.sendMessage`).

**Evidence:** Interactive path uses `ctx.reply` with per-provider impls; durable/background path uses `BotProvider.sendMessage` via the outbox poller; webhook path enqueues text only, never the queued handler. Chunking/send/error-wrapping is re-implemented 3× across providers. This is pre-existing intentional lane separation (agent gets immediate+outbox dual-write with grace; webhook/scheduler get durable-only). Unifying would change delivery semantics (grace windows, timing, failure visibility) — contract-touching, so not done without user approval.

### IG-03: Mention/trigger model differs by provider — CONFIRMED, flagged
**Location:** `src/providers/whatsapp.ts:673` (mentionedIds), `src/providers/discord.ts:262` (mentions.users), `src/providers/telegram.ts:463-471` (text.includes(botId|@username) + leading-slash regex), `src/agent/index.ts:553` (re-tests `/`).

Telegram double-counts commands as mentions. Fixing changes trigger semantics per platform — flagged, not changed.
