## Critical bugs (fixed in this pass)

### C-01 `AppRuntime.stop()` resolved before the teardown it was waiting for
`src/runtime/AppRuntime.ts:502` — `if (this.stopping) return;` answered every
caller that arrived during a teardown with an already-resolved promise. Reachable
path: `webhookServer.start()` throws → `start()`'s catch calls `stop()` (first
owner) → a SIGTERM then runs `bootstrap`'s `shutdown()` → `await runtime.stop()`
returns immediately → `closeDatabase()` and `forceExit(0)` while
`provider.stop()` / `drainOutbox()` are still using the handle.
**Fix:** `stop()` memoises one `stopPromise`; every caller awaits that teardown,
and `start()` awaits an in-flight teardown before it re-arms anything, so a
restart that begins mid-shutdown waits instead of rebuilding hooks that the
teardown then removes.

### C-02 The interrupted-boot path tore the runtime down twice
`src/runtime/AppRuntime.ts:382` — when a shutdown landed while
`Promise.allSettled(providers.start())` was pending, `stop()` had already run
`teardown()`, and `start()` then called `teardown()` again: a second
`drainOutbox()` claiming rows against providers the first pass had stopped.
**Fix:** the branch now `await this.stop()`, which joins the running teardown.

### C-03 A live redelivery during inbox backoff was silently discarded
`src/messaging/InboxService.ts:140` — `claim` required `available_at <= now`, so
a duplicate admission (the row is `failed` with a backoff) failed the claim, the
task returned with no log and nothing re-drove the row. WhatsApp's decrypt-retry
re-emit is the one real redelivery path in the codebase, and this window
suppressed it.
**Fix:** `claim(id, owner, { allowBackoff })`, used for duplicate admissions;
`AppRuntime` now logs when a claim fails. The state/lease predicate is unchanged,
so an in-flight turn is still never preempted (test:
`MessagingService.test.ts` "allowBackoff never preempts a turn that is still
running").

### C-04 An interrupted first migration permanently bricked startup
`src/db/migrations.ts:258` — the "schema exists without a ledger" guard counted
`__drizzle_migrations` itself as an application table. Drizzle creates that table
outside the migration transaction, so a crash in that window left an empty
database that could never migrate.
**Fix:** the ledger table is excluded (as `database_leases` already was).

### C-05 A stop/start cycle left the message queue permanently stopped
`src/utils/MessageQueue.ts:229` — `stop()` is permanent, while `AppRuntime`
explicitly supports restart in one process. After a restart every `enqueue`
returned `false` (80 × 25 ms backpressure, then a drop) and `/ready` answered 503
forever.
**Fix:** `MessageQueue.resume()`, called from `AppRuntime.start()`.

### C-06 Discord reaction feedback could never arrive
`src/providers/discord.ts:52` — the 👍/👎 handlers were registered, but
`GuildMessageReactions` / `DirectMessageReactions` intents and `Partials.Reaction`
were never requested, so discord.js never delivered the events. Discord was the
only platform whose feedback never reached `recordReactionFeedback`.
**Fix:** the three are requested.

### C-07 WhatsApp round video notes were dropped
`src/providers/whatsappParser.ts:41` — `ptvMessage` was missing from
`MEDIA_TYPES`, so a video note parsed as a text message with no body:
`hasMedia:false`, no descriptor, nothing delivered.
**Fix:** the type is recognised. Baileys 7.0.0-rc14 already maps
`ptv: 'Video'` in `MEDIA_HKDF_KEY_MAPPING`, so the existing downloader derives
`WhatsApp Video Keys` correctly and no re-keying is needed. (An earlier version
of this patch added a re-key helper on the belief that the mapping had no `ptv`
entry; review caught it and the helper was removed with its test.)

### C-08 A truncated reasoning-only stream shipped raw chain of thought
`src/utils/ModelRouter.ts:510` — the "empty stream" and "unsafe fallback"
decisions used `stripThinkTags`, which only matches a closed `…` block. A stream
that ended mid-reasoning counted as having content and was returned as the
answer.
**Fix:** both decisions use `stripPartialThinkTags`; the router also gains an
`onRestart` hook so the consumer drops the abandoned provider's chunks (the agent
resets its accumulation), instead of appending the next provider's answer to a
half-written reasoning block. The non-streaming `hasUsefulResponse` got the same
treatment, so a non-streamed completion that ends inside an open reasoning block
is no longer accepted as an answer.

### C-09 A failed Telegram unban reported a clean removal
`src/providers/telegram.ts:889` — removal is ban-then-unban and the unban
rejection was swallowed, so a member stayed banned forever while the tool
returned success.
**Fix:** unban failures are collected and reported.

### C-10 Flow sessions were cleared before the notice was sent
`src/core/FlowHandler.ts:472` — `clearSession()` ran before `ctx.reply()`. A
provider error on the reply left the flow gone and the retried turn processing
the user's step text as a new message.
**Fix:** the notice is sent first, so a failed reply leaves the state retryable
(applies to the stale-flow, missing-processor and `/cancel` paths).

### C-11 `SpeakTool` ignored the tool-timeout signal
`src/tools/SpeakTool.ts:70` — `execute` accepted no third argument and forwarded
`ctx.signal`, so a timed-out `/speak` kept synthesising and transcoding after the
tool timeout had already answered.
**Fix:** `signal ?? ctx.signal` like `TranscribeTool`/`MediaConvertTool`.

### C-12 Unbounded response bodies in two services
`src/utils/transcription.ts:90` (`response.json()`) and
`src/utils/EmbeddingService.ts:172` (`response.text()` before slicing) buffered a
whole body; the timeout bounds time, not size. This is exactly what
`utils/httpBody.ts` exists for and what `searchUtils` already does.
**Fix:** both read through `readResponseTextBounded`.

## Integration gaps (fixed)

### I-01 Retention predicates could not use an index
`src/db/retention.ts:93` wrapped every timestamp in `CASE WHEN col > 1e11 …`,
which prevents a range seek. Measured with `EXPLAIN QUERY PLAN` on a fully
migrated database, and with timings where they were meaningful:

| Query | Before | After |
|---|---|---|
| clear `raw_message` | `SCAN messages` | `SEARCH messages USING INDEX messages_created_at_idx (created_at<?)` |
| delete expired `messages` | `SCAN messages USING COVERING INDEX …` | `SEARCH messages USING COVERING INDEX … (created_at<?)` |
| delete expired `flow_sessions` | `SEARCH … (updated_at<?)` | unchanged |
| `reminders` | `SEARCH reminders USING INDEX reminders_due_idx (is_sent=?)` | unchanged (planner prefers the state index) |

Timings (bun:sqlite, migrated schema):

- **raw-message pass, 100k rows with a 4 KiB `raw_message`**: **208 ms → 11 ms**
  for the dry-run count. This is the pass that mattered: the old plan was a full
  *table* scan, so it read the largest column for every row.
- **`messages` delete loop, 200k rows, 150k eligible**: 5.3 s → 5.5 s — no
  change, because a delete of three quarters of the table is dominated by the
  deletion, not the scan. The plan still changes to a seek.
- Dry-run count, 200k rows, 0.1 % eligible (`raw_message` NULL): 14.8 ms → 17.8 ms,
  i.e. within noise. The seek is a plan improvement, not a measured win, for a
  covering-index count of that size.

The mixed-unit `CASE` is kept (rows written in seconds still exist); the new
leading plain comparison is implied by it and only exists to give the planner a
range. Verified equivalent on the same data (identical eligible counts; the
benchmarks that differ do so because their seeded timestamps differ).

### I-02 Backup manifests always recorded `latestMigration: null`
`src/db/backup.ts:318` — `backupDatabase` never passed the migrations folder, so
`migrationSummary` could not name the newest journal entry.
**Fix:** `BackupOptions.migrationsFolder` (defaulting to the shipped folder).

### I-03 The migration lease is never renewed — NOT fixed, see deferred
`src/db/index.ts:253` — a table rebuild longer than the 300 s TTL lets a second
process pass the same acquire and run `migrate()` concurrently; only the runtime
lease has a heartbeat.

A renewal timer was implemented and then **removed**: `drizzle-orm/bun-sqlite`'s
`migrate()` is synchronous, and so is every step between the acquire and the
`finally` that clears the timer, so the interval could never fire — the patch
would have recorded a protection the code did not provide (caught in review).
Genuine options are a renewal on a worker thread, or accepting the window; both
belong with D-06-style infrastructure decisions. Deferred.

### I-04 `bun run db:retention` could create and then delete against a wrong database
`scripts/runRetention.ts` opened whatever `ELASTRAX_DB_PATH` resolved to in
create mode. A typo produced a stray empty database and an opaque
`no such table: messages`; a valid-but-wrong path ran retention elsewhere.
**Fix:** the script refuses a missing file or a database without the messaging
tables.

### I-05 Every admin mutation failed behind a Host-rewriting proxy
`src/admin/routes.ts:141` — `Origin` was compared with the raw `Host` header
only. nginx's default `proxy_set_header Host $proxy_host` makes the browser's
`Origin` unmatchable, so reads worked and every mutation answered 403, while
`shouldUseSecureCookie` already trusted `X-Forwarded-Proto` from the same proxy.
**Fix:** `X-Forwarded-Host` is accepted as a second candidate (a cross-site
request cannot set it without a preflight this server does not answer, and the
CSRF token is still required).

### I-06 `source: rotation` made the login throttle do O(10 000) work per request
`src/admin/routes.ts:211` called `throttle.prune()` unconditionally before
`attempt()`, and `prune` walks the whole bucket map.
**Fix:** the sweep runs at most once per window, inside `attempt`.

### I-07 The dashboard's config view listed a variable nothing reads
`src/admin/data.ts:434` — `EMBEDDING_ENDPOINT` (never read) in
`CONFIG_ALLOWLIST`; `EMBEDDING_API_URL` (the real name) was missing.
**Fix:** swapped.

### I-08 Baileys auth-state reads were N+1
`src/utils/useDBAuthState.ts:82` — one `SELECT` per requested key id, on the
crypto path where Baileys asks for session/pre-key *sets*.
**Fix:** one `IN (…)` query per call.

### I-09 `bun run fixtures:dump` ran a second, unhardened dumper
`scripts/dumpFixtures.ts` duplicated `dumpFixtures()` with its own unbounded
`SELECT` over every message row (blobs included), a hardcoded directory and no
`FIXTURE_DUMP_DIR` support.
**Fix:** the script is now argument parsing plus a report; `dumpFixtures()` gained
`force` and returns a summary (`FixtureDumpSummary`), so the hardened path
(bounded read, 0700/0600, `EACCES`/`EROFS` handling, `FIXTURE_DUMP_DIR`) is the
only one.

## Declared behaviour changes

Two changes alter existing behaviour deliberately; both are small and were
reviewed:

- **B-01** `transcribeVoiceIfAny` (`agent/index.ts:540`) now treats a rejected
  `ctx.mediaReady` as "no transcript" instead of aborting the turn. Previously a
  failed media download aborted the whole turn from this path *before* the AI
  phase. The AI-phase `await ctx.mediaReady` still throws on purpose: the user
  asked about media the bot could not read, and `test/agent.test.ts` pins the
  explicit error there.
- **B-02** `DiscordProvider.stop()` now awaits `client.destroy()` (and the two
  login-failure paths observe it). Teardown therefore waits for the gateway to
  close instead of returning early, and a rejection can no longer escape as an
  unhandled rejection (fatal under Bun's default policy). It is bounded by
  `AppRuntime`'s 10 s provider-stop race.

## Architecture / performance notes

- **A-01 Retention (`messages`, `raw_message`, `reminders`, `flow_sessions`) now
  seeks instead of scanning** — see I-01. `message_inbox`/`message_outbox` still
  cannot use an index: their predicates are
  `state IN (…) AND COALESCE(completed_at|sent_at, updated_at) < ?`, and a
  `COALESCE` over two columns cannot be range-seeked. Fixing that needs either a
  generated column or an index on one chosen timestamp, which changes which
  timestamp decides expiry — a policy decision, not a refactor (deferred).
- **A-02 `getRoomKeyStats` issues ~24 `count(*)` scans per admin room-list
  request** (`src/db/rooms.ts:455`). Admin-only and low traffic; the schema-catalog
  probes are already memoised. Left as-is; a short-TTL cache would be the fix if
  the dashboard ever gets slow.
- **A-03 `platformsForRemoteRoomId` issues up to six SELECTs per webhook
  destination** (registry probe per platform plus a legacy probe) on the intake
  path. Correct, but it would collapse into one query; left for a dedicated
  change because `resolveRoomKeySync` is shared with non-webhook callers.
- **A-04 LLM calls still ignore `ctx.signal`** (`agent/index.ts:1324`, `:1467`):
  an aborted turn (scheduled-task timeout, queue abort) keeps the HTTP request
  alive until `AI_TIMEOUT_MS`. Threading a signal through `ModelRouter` →
  `AIClient` is straightforward, but the fallback policy has to decide what an
  abort means (retry the next provider or stop), so it needs its own design note.

## Optional improvements (not implemented)

- **O-01** `extensionForMime` (`mediaShared`) and `mimeToExt` (`mimeTypes`) answer
  the same question differently (`image/jpeg` → `jpeg` vs `jpg`,
  `audio/mp4` → `mp4` vs `m4a`). They serve different purposes (generic fallback
  vs canonical conversion table); unifying them changes user-visible filenames.
- **O-02** `AuthService.meetsRequirement`, the async `resolveRoomKey`,
  `isCanonicalRoomKey`, `assertRoomKeyMatches` and `DatabaseHandle.checkpoint`
  have no production caller. They are coherent, documented utilities with tests,
  so they are not deleted here (rule: prove it is unused *and* worthless).
- **O-03** Provider `sendMessage` returns `void`, so `message_outbox.provider_message_id`
  can never be populated (`AppRuntime.ts:1006` checks for a string no provider
  returns). Wiring real ids touches the `BotProvider` contract and every sender
  lane; worth doing, but as its own change.
- **O-04** `ParameterValidator` compiles `new RegExp(schema.pattern)` per value,
  and `TOOL_MUTATION_COST_LIMIT` / `MENFESS_TARGETS` are re-parsed per call.
  Cheap individually; a small memo cache would tidy the per-message path.
- **O-05** WhatsApp media downloads cannot be cancelled: Baileys forwards only
  `dispatcher` and `headers` to `fetch`, so our `AbortSignal` is ignored until the
  next chunk. The timeout therefore still holds a media slot until undici's own
  body timeout. Fixing it means supplying a custom undici dispatcher (upstream
  change) or racing the stream and releasing the slot explicitly.

## Follow-up after the pass (2026-11-19, at the operator's request)

The startup failure `AI_OMNIROUTER_BASE_URL must use https unless it points to a
loopback address` hit a real deployment: a self-hosted inference server on a
private network (`http://100.150.0.4:8080/v1`) that has no certificate. The
https rule cannot relax itself for private ranges — validation cannot reliably
tell a private address from a public one, and the key travels in cleartext — so
the relaxation is an explicit opt-in:

- **`ALLOW_INSECURE_HTTP_ENDPOINTS`** (boolean, default `false`) accepts plain
  `http://` for the credential-bearing endpoints that otherwise require https:
  `AI_API_BASE_URL`, every `AI_<NAME>_BASE_URL`, and `TRANSCRIBE_ENDPOINT`.
  Invalid values fail startup; a startup warning names the cleartext exposure.
- The scope is exactly those keys. `JELLYFIN_EXTERNAL_URL` still requires https,
  URLs with embedded credentials are still refused, and the self-hosted media
  services (`SEARXNG_URL`, `SEERR_API_URL`, `JELLYFIN_API_URL`) keep their
  existing plain-http allowance.

Tests: `test/config.test.ts` covers acceptance, the multi-provider and
transcription forms, the unchanged limits, and the invalid-value rejection.
This is a documented opt-out, so it does not relax D-09 (validating
`TTS_BASE_URL`/`EMBEDDING_API_URL`, which are not validated at all yet).
