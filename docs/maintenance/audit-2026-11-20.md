## Critical / high

### C-01 A half-open provider could be disabled for the life of the process
`src/utils/ModelRouter.ts:465` — `acquireProvider` sets `probeInFlight` for a
`half-open` circuit, and only `markProviderFailure` / `clearProviderCircuit`
clear it. A stream consumer that abandons the generator (turn abort, or a throw
in the caller's `for await` body) unwinds a `return` completion, which runs
`finally` but not `catch`. The probe stayed set, `getCandidateProviders` only
re-arms an `open` circuit, so every later request silently skipped that provider.
With one configured provider every turn then failed with `AllProvidersOpenError`
until a restart.
**Fix:** a `finally` in the streaming loop releases the probe when the call did
not reach a terminal state (`settled` flag), without recording a failure.
Test: `ModelRouter.test.ts` "releases a half-open probe when the consumer
abandons the stream".

### C-02 A ledger from an older journal layout bricked startup
`src/db/migrations.ts:347` — `inspectMigrationState` required each applied row's
`created_at` to equal the journal's `when`, while this repository deliberately
renumbers `when` to `1..N` and earlier journals used `null` / epoch
milliseconds (verified in `git log` on `_journal.json`: commits `b8af96d`,
`13e32e1`, `3925aec`, `69f8f8f`). A database migrated back then can never match
today's values, and the guard throws before any migration runs.
**Fix:** rows are identified by position (already proven by the per-position
checksum) and the ledger may only be *longer* than the journal, which is still
refused. `latestCreatedAt` now comes from the journal so it agrees with
`db_schema_meta.schema_version`.
Tests: "accepts a ledger written before the journal used sequential `when`
values", "refuses a ledger with more rows than the journal".

### C-03 Restore refused every backup taken before the newest migration
`src/db/backup.ts:186`, `scripts/dbBackup.ts:89` — restore required
`schema_version === latest journal when`, and `requireCurrentSchema` also ran the
current contract. Shipping any migration therefore made every existing backup
unrestorable — exactly the "I upgraded and it broke" case restore exists for.
**Fix:** `RestoreOptions.maxSchemaVersion` refuses only a snapshot *newer* than
the build; the script restores, then runs `ensureDatabaseSchema` on the copy and
validates the contract. Test: "accepts a snapshot at or below the current schema
and refuses a newer one".

### C-04 Webhook events from different senders collided in the outbox
`src/runtime/AppRuntime.ts:701` — the replay cache keys on
`route \0 source \0 id`, but the outbox idempotency key omitted `source`. Two
senders reusing a small numeric `x-webhook-id` on the same route produced one
key; the second event was answered `202 duplicate` and never delivered.
**Fix:** the source is part of the outbox key. Test: `roomKeyDelivery.test.ts`
"two senders reusing an event id on the same route both get delivered".

## Bugs (fixed)

- **B-01** `/convert gif` with any `resolution`/`fps` override always failed
  validation: `MediaConvertTool.mergeFfmpegArgs` folds the override into the
  GIF palette chain (`fps=10,scale=320:-1:flags=lanczos,...`) and
  `FFmpegConverter.isAllowedFilterChain` did not accept that segment. The
  allow-list now accepts it (still an anchored, enumerated shape).
- **B-02** Streamed tool calls that arrive without an `id` produced
  `tool_call_id: ""`; two of them made the follow-up request invalid *after* the
  tools had run. Ids are synthesised (`call_<uuid>`).
- **B-03** A malformed `usage` object in the final stream chunk (for example
  `"prompt_tokens": "12"`) threw after the whole answer had been streamed, and
  the reply was replaced with "internal error". Stream usage is now advisory.
- **B-04** `SSEDecoder.push` checked the buffer cap before draining, so one read
  carrying more than the cap in *complete* events was rejected as an overflow.
  The cap is now enforced on the residual buffer (which still bounds an
  unterminated line).
- **B-05** The conversation-summary watermark was a read-modify-write with no
  guard, and a scheduled run bypasses the per-room queue. Overlapping turns could
  move the watermark backwards and re-summarise messages. The write now runs in
  an immediate transaction and never moves backwards.
- **B-06** The "internal error" placeholder was persisted as an assistant turn,
  so the model received it as its own previous answer on every later turn.
  Fallback detection also used a comparison against the localised text, which
  could double-send a model answer that happened to match it. Both now use an
  explicit `usedFallbackError` flag.
- **B-07** `WhatsAppProvider.start` awaited a 10 s socket close and then created
  a new socket without re-checking the generation; a `stop()` in that window was
  followed by a live socket under a stale generation.
- **B-08** WhatsApp and Discord `sendMessage` resolved successfully for empty or
  whitespace-only text (Telegram already refused), so the outbox recorded a
  delivery that never happened.
- **B-09** Telegram: a failed attachment download left `descriptor.error` empty;
  `sendVoice` received MP3 (it accepts only OGG/OPUS); captions were unbounded
  (1024 max). Fixed all three, with the caption clamp shared through
  `clampCaption` in `textChunking.ts` (WhatsApp used the same gap).
- **B-10** Deleting an already-deleted message was reported as a hard failure on
  Telegram and Discord; the requested end state already holds.
- **B-11** Discord's `reconnectAttempts` was not reset after a gateway resume, so
  the next failure started from the maximum backoff.
- **B-12** The admin login throttle charged successful logins and advertised a
  hard-coded `Retry-After: 60`. Only failures are charged now, and the header
  reports the real remaining window.
- **B-13** Unauthenticated webhook requests read up to `maxBodyBytes` and
  attempted the secret check without any throttle (the token bucket ran only
  after authentication). A per-peer bucket now runs first.
- **B-14** `scripts/backfillEmbeddings.ts` selected blank rows, which
  `EmbeddingService` deliberately maps to an empty vector, and threw on it inside
  the transaction — so every run failed on the same row forever. Blank rows are
  excluded and an empty vector is skipped.
- **B-15** `Scheduler.processReminders` looked up the sender by the stored
  `platform` string, while registration uses canonical names; a row holding
  `WhatsApp` resolved a valid target but no sender, and was retired after the
  defer budget.
- **B-16** `BaseHttpClient` swallowed `RESPONSE_TOO_LARGE` from an error body and
  reported a generic `HTTP_ERROR` with no detail.
- **B-17** `pruneBackups` sorted by `Date.parse(manifest.createdAt)` without
  validating it; a `NaN` comparator left the order implementation-defined and
  could delete a valid recent backup. `parseManifest` also accepted a manifest
  with no `database` object, which produced a `TypeError` instead of a clear
  refusal.
- **B-18** `dbBackup restore` could publish next to a leftover `-wal`/`-shm`,
  which SQLite replays into the new file. Refused.

## Integration / consistency (fixed)

- **I-01** `FlowHandler.pruneAllExpired` read every row and wrote unconditionally
  without the per-key lock; a flow started in that window was clobbered or
  deleted. It now takes the lock and re-reads inside it.
- **I-02** `FlowHandler.clearSessionInternal` deleted the row fire-and-forget
  after releasing the lock, so a session written in between could be removed. The
  delete is awaited inside the lock.
- **I-03** Room knowledge ingest checked the quota, then inserted chunks one by
  one with no transaction: two concurrent ingests could both pass, and a failure
  part-way left an orphan document. Inserts and the quota re-check now share one
  immediate transaction; usage is counted in SQL (`CAST(content AS BLOB)`), so
  the room's text is no longer read into JS.
- **I-04** `pruneDigestMarkers` used `LIKE 'digest:%'`, which cannot use the
  `app_kv` primary key without `case_sensitive_like`, and ran twice a minute.
  Replaced with a key range.
- **I-05** The internal-error path and the streaming-final-edit path compared
  user-visible text instead of carrying state (see B-06). `formatToolAction`
  language threading and webhook `textVariants` in the newer i18n commit were
  reviewed and are consistent (every `dispatch` call supplies both locales, and
  `pickWebhookText` falls back to `text`).
- **I-06** The admin config inventory's secret heuristic matched any name
  containing `token`, so `AI_MAX_TOKENS` was reported as "set" instead of its
  value. It now matches whole `_`-delimited segments.
- **I-07** The runtime lease was acquired *after* the migration lease was
  released, leaving a window where a second process could win; it is now taken
  while the migration lease is still held. `close()` releases the lease after the
  WAL checkpoint instead of before it.
- **I-08** A 413 webhook body was released but never cancelled, leaving Bun to
  drain a connection nobody was reading.

## Architecture / performance notes (not changed)

- **A-01** `validateSchemaContract` runs `PRAGMA foreign_key_check` on every boot,
  which scans every table with a foreign key. Correct, but it is boot latency on a
  large database; gating it on `pending.length > 0` would be the fix if measured
  to matter.
- **A-02** The admin room list collapses document chunks in JS after selecting
  every chunk row for up to 200 rooms. A SQL aggregation would need the
  `<documentId>_<ordinal>` split expressed in SQLite; admin-only traffic, and
  bounded by the room quota, so it stays.
- **A-03** `HealthMetrics.toolStats` keeps an entry for every tool name ever seen;
  a renamed plugin tool leaves a permanent entry. Removing entries absent from the
  registry after `/reload` is the fix, but it needs the registry to hand its live
  name set to the metrics module.
- **A-04** `Scheduler.processReminders` processes up to 50 due rows strictly
  sequentially, and one scheduled agent task may run for up to
  `SCHEDULED_TASKS_TIMEOUT_MS` (default 120 s). A due text reminder behind such a
  task waits. Fixing it means settling deliveries concurrently while keeping the
  claim and state writes serialised — a design change, not a patch.
- **A-05** (carried from pass 6) LLM calls still ignore `ctx.signal` (A-04 there);
  the fallback policy has to define what an abort means.

## Optional improvements (not implemented)

- **O-01** `globalMediaByteBudget` (200 MiB) is shared by up to four concurrent
  downloads that grow their reservation as they receive bytes; four chunked
  downloads of ~50 MiB each can each block on their next chunk while holding what
  they already have, so all four stall until the 60 s per-download timeout.
  Fail-fast acquisition (reject instead of wait) or sizing the pool for the real
  concurrency would fix it; both change user-visible behaviour under load.
- **O-02** `OutboxService` re-enqueue keeps `MAX(available_at, …)` while resetting
  `attempt_count`, so a row re-enqueued every minute inherits the previous
  exponential backoff. This is tied to the tested re-enqueue semantics (D-08 of
  pass 6), so it is left as a decision.
- **O-03** `room_keys` grows for every `(platform, remoteRoomId)` pair, including
  pairs with no `chat_rooms` row, and no retention sweeps it. A GC rule is a
  policy decision.
