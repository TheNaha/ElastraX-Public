## Tech Debt and Duplication

### TD-006: Room-key format still built manually in two places (CONFIRMED duplication)
**Location:** `src/core/FlowHandler.ts:252-254`; `src/tools/RoleTool.ts:42-55`

**Evidence:** `src/core/roomKeyFormat.ts` is the single source of truth for the canonical `room:<platform>:<id>` format and documents that "every producer calls `toRoomKey()`". It was created precisely to unify seven previous producers (`db/rooms.ts`, `agent/roomKey.ts`, `messaging/roomKeys.ts`, `utils/AuthService.ts`, `utils/IdentityService.ts`, `core/FlowHandler.ts`, `tools/RoleTool.ts`). However:

- `FlowHandler.ts:252-254` builds `room:${session.platform}:${session.roomId}` via string concatenation instead of `toRoomKey()` (with an "already canonical" guard that must be preserved).
- `RoleTool.ts:43` builds `room:${platform}:${currentScope}` via concatenation instead of `toRoomKey()`.
- `RoleTool.ts:44-49` re-implements `legacyScopeFor` inline (`startsWith`/`slice` on `room:${platform}:`) even though `legacyScopeFor` is already imported from `../utils/AuthService` (line 31).

This contradicts `roomKeyFormat.ts`'s own contract and means a key built by FlowHandler/RoleTool could disagree with a key built by the unified producers (no trimming in FlowHandler; RoleTool bypasses the shared `legacyScopeFor`).

**Proposed fix:**
- `FlowHandler.ts`: import `toRoomKey` from `../core/roomKeyFormat`; replace the concatenation branch with `toRoomKey(session.platform, session.roomId)`, keeping the existing "already canonical" guard. (Use the leaf `roomKeyFormat` import — not `db/rooms` — because `db/rooms.toRoomKey` throws on empty input and would change behavior; FlowHandler's inputs are truthy per its guard, so the non-throwing format helper is behavior-preserving plus trimming.)
- `RoleTool.ts`: import `toRoomKey` from `../core/roomKeyFormat`; replace the inline concatenation with `toRoomKey(platform, currentScope)` and the inline `startsWith`/`slice` with the already-imported `legacyScopeFor(platform, scope)`.

**Risk:** Low. Behavior-preserving for all truthy inputs (the only inputs these code paths receive). RoleTool change is literally replacing inline code with the already-imported `legacyScopeFor`. Verified by `FlowHandler.test.ts` and `RoleTool.test.ts`.
