## Duplication Found — Safe to Fix (committed on branch maintenance-pass-2026-11-10)

### TD-10: Calendar date reconstruction triplicated in Scheduler.ts — RESOLVED

**Location:** `src/utils/Scheduler.ts:120-183`

**Evidence:** `nextMonthly`, `nextCalendarOccurrence`, and `addCalendarDays` each reconstruct a `Date` from component getters (`getFullYear`, `getMonth`, `getDate`, `getHours`, `getMinutes`, `getSeconds`, `getMilliseconds`). `nextCalendarOccurrence` and `addCalendarDays` are virtually identical (differ only in parameter name).

**Fix:** Extracted `dateFromComponents(source, overrides)` helper; all three functions now delegate to it. Intra-file only, no behavior change, no public contract.

### TD-11: FlowHandler duplicate delete-try/catch blocks — RESOLVED

**Location:** `src/core/FlowHandler.ts:334` and `:420`

**Evidence:** Two nearly identical catch blocks:
```ts
try { await db.delete(flowSessions).where(eq(flowSessions.id, key)).run(); } catch (error: unknown) { logger.warn({ err: error, key }, '[FlowHandler] ... failed'); }
```
Same file, ~85 lines apart, same logic, same log shape.

**Fix:** Extracted `safeDeleteSession(key, reason)` private static method; both sites call it. No behavior change.

### TD-12: `AI_VERBOSE_LOGS === 'true'` inline check duplicated — RESOLVED

**Location:** `src/agent/index.ts:462` and `src/utils/ModelRouter.ts:362`

**Evidence:** Both sites use `process.env.AI_VERBOSE_LOGS === 'true'` inline instead of the canonical `readBooleanEnv()` from `src/config/runtime.ts`.

**Fix:** Both now use `readBooleanEnv(process.env.AI_VERBOSE_LOGS, false)`. Import added where missing.

### TD-13: `YTDLP_PATH || 'yt-dlp'` default duplicated — RESOLVED

**Location:** `src/tools/DownloadTool.ts:162` and `src/utils/HealthMonitor.ts:191`

**Evidence:** Both sites use `process.env.YTDLP_PATH || 'yt-dlp'` inline.

**Fix:** Added `getYtDlpPath()` to `src/config/runtime.ts`; both call sites use it.

### TD-14: `new Date().toISOString()` — 17 occurrences across 9 files

**Location:** `src/utils/date.ts` (new `nowISO()` helper added), plus 17 call sites not yet routed through it

**Evidence:** `new Date().toISOString()` appears in MediaBindTool, AppRuntime (2x), admin/data (5x), db/backup (2x), DigestService, ConversationSummarizer, ReminderTool, WebhookServer (2x), feedback, date.ts itself.

**Fix:** Added `nowISO()` helper to `src/utils/date.ts`. Routing all 17 call sites through it is left as optional (invasive, low marginal benefit — timestamps are intentionally free-form unlike `dateKey` which is centralized).

## Error-Handling Hygiene (committed)

### EH-01: Swallowed rollback error — RESOLVED

**Location:** `src/db/runtime.ts:140-141`

**Evidence:** `withImmediateTransaction` caught `rollbackError` with `void rollbackError;`, silently swallowing rollback failures. If ROLLBACK itself fails, the transaction state is unknown and the original error is still re-thrown — but the rollback failure is invisible.

**Fix:** `logger.warn({ err: rollbackError }, 'Rollback failed during transaction error handling');`

### EH-02: Silent embedding-update failure — RESOLVED

**Location:** `src/tools/MemoryTool.ts:198`

**Evidence:** `updateMemoryEmbedding` failure was logged at `debug` level only and swallowed. The memory row was already inserted without an embedding; nothing retried or flagged it.

**Fix:** Upgraded to `log.warn` so operators can see embedding failures.
